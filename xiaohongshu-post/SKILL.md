# 小红书图文策划与制作

仅在用户明确调用 `$xiaohongshu-post` 或明确要求使用本 skill 时应用。普通提及小红书不触发本 skill。

## 范围与默认偏好

根据本次请求提供完整图文或其中一部分。只要标题正文，就直接写文案；只要策划，就停在方案；明确要求生成或修改图片，就执行已授权的范围。已有决定直接沿用，避免重复确认。

以下是用户偏好，可被当前要求覆盖：中文、务实克制、偏个人经验分享；Whiteboard 白板手绘风，白底、黑色马克笔字、少量雾蓝强调，3:4 竖版。每张一个重点，标题在约两秒扫视内可辨识。两秒是设计目标，不是经过测试的效果承诺。

## 1. 从素材中找到本篇主线

- 先读取用户提供的资料和相关项目说明；能从资料确认的信息不重复询问。引用其他任务时，仅在实际读到内容后才使用，无法访问就说明限制。
- 区分可核实的功能、用户确认的亲身经历、计划中的能力和演示案例。不编造工作年限、公司背景、效果数字或成功率。
- 明确受众、核心价值、期望行动。信息不足且影响成稿时，一次问一个关键问题，并给出推荐方向与理由。
- 选择个人经验、项目介绍或教程主线。个人背景与产品功能内容都很多时，可以建议拆成两篇；只制作本次授权的篇目。
- 功能用使用场景解释，核心价值由素材决定，不把 AI、开源或功能数量默认当作最大卖点。

## 2. 先安排阅读顺序

需要多图时，列出分页表：页码、核心问题、图片标题、必要短文案、示意画面。

- 一张只回答一个核心问题；封面说明主题和读者，后续逐页展开，结尾提供必要行动入口。
- 张数由内容决定，可以从六张拆为九张，也可以更少。不要为了固定张数塞满页面，也不要为了凑数重复内容。
- 图内通常只保留一个大标题、两三条短说明或一幅简单流程。主题列表等内容按实际需要调整。
- 删除宣传口号、无信息量的英文、重复解释和装饰性小字。留白是设计的一部分。
- 图片负责快速理解，正文补充来源、动机、场景和细节，不逐页抄写图片。
- 虚构职位、回答、简历和记录明确标注示例；真实个人资料只使用用户允许公开的部分。
- 地址优先只放最后一页。确认地址和发布状态，区分预告与正式介绍，不暗示尚未开放的入口已经可用。

## 3. 确定视觉后制作图片

使用可用的 imagegen 技能和图片工具执行生成或编辑；细节见 [visual-guide.md](references/visual-guide.md)。工具不可用时如实说明，不把提示词冒充已生成图片。

新风格且用户希望共同确认时，先做一张代表页再扩展；已有认可样张，或用户已要求直接生成整套时，按现有决定执行，不新增审批步骤。

把样张作为风格参考时，明确只参考画风，不能把封面文案带进每页。为每页提供准确文字，保持统一的品牌位置、页码、配色和字形。生成后逐页查看；修复错字、漏字、错误地址、透明背景、裁切和明显风格漂移。只重做受影响的页面。

## 4. 写标题和正文

- 默认给出一个推荐标题和可直接复制的正文；需要比较方向时再给少量备选。
- 标题突出具体内容或使用价值，避免未经证实的效果承诺与夸张措辞。
- 个人分享用已确认的真实经历展开；没有经历依据时使用客观功能说明。
- 正文按来源或动机、主要场景、适用对象、开始方式组织，按内容删减。少量相关标签即可，表情符号可选。
- 图文术语、功能和行动入口保持一致。本次项目事实不能永久固化为通用模板。
- 如果需要宣称平台当前字数、图片数量、链接等规则，先核实；不把历史经验当成实时限制。

## 5. 整理交付

按页编号保存最终 PNG 图片，并保存本次需要的发布文案与实际使用的提示词。默认不生成或保留 ZIP 等压缩包，仅在用户明确要求时打包。检查最终图片的页数和顺序。输出沿用当前形式：主题目录中存放按页编号的独立图片及提示词文件；最终回复用简洁说明和可点击的绝对路径，按需列出目录或按发布顺序列出单图链接。

使用主题专属输出目录，避免覆盖其他任务。修改版保留可辨识版本；只有用户要求清理时才删除指定旧稿。Windows 路径使用 `D:/...` 或 `C:/...`，不要拼成 `/C:/...`。

最后简洁说明本次完成的内容、输出位置和必要限制。图文制作不包含自动发布或发送给他人。
